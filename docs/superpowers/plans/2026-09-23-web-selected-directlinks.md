# Web selected directlinks implementation plan

**Goal:** 网页只提取当前目录勾选的普通文件，整分享递归仅保留 API。
**Architecture:** ShareFileSelector 保留原下载选择事件（含文件夹折叠），增加独立普通文件事件，从当前列表与选中集合计算，不用折叠后的文件夹 ID。网页提取按钮只在选择步骤显示并强制非空。下载函数与 sidecar API 不修改。
**Tech Stack:** Vue3 / TypeScript / Vitest。

- [x] 先写失败测试：输入步骤无提取按钮；选文件后非空才能提取；请求必须携带普通文件 IDs/paths；结果及逐文件复制继续有效。
- [x] 选择器回归：当前列表普通文件全选；文件夹不能进入提取列表；进入目录不会请求其他目录；子文件全选不合并为文件夹；原下载事件保持原样。
- [x] 增加 `update:extractFiles` 事件，由 `currentFiles.filter(f => !f.is_dir && checkedFsIds.has(f.fs_id))` 生成，导航/分页/勾选后同步。加载目录时传空列表防误提取。
- [x] 父组件增加 extractFiles；提取前拒绝输入步骤/空列表，只发普通文件ID/path快照；移除输入步骤按钮和递归提示，选择页说明当前列表范围。
- [x] 运行前端专项测试、类型检查/构建、Rust API回归及 diff 检查。记录实际验证结果。

用户已确认六项交互规则；入口保留“选择分享/提取文件”。为保持下载功能，文件夹勾选仍供下载使用，不作为网页提取项；选择页明确提示，提取计数只统计当前目录普通文件。全选范围是当前已加载列表，不暗中加载全部分页或子目录。

验证：20项前端专项测试通过；vue-tsc及Vite构建通过（既有大chunk警告）；Rust 30项测试通过，包括API无选择递归。新增回归先观察失败再修复。原转存/同步组件通过可选 extraction prop 保持原行为。此次未做服务器部署，也未声称解决历史上游转存路径错误。
